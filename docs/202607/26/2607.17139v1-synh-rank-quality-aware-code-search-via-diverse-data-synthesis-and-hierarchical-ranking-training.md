## 摘要
代码搜索通过促进高效的代码复用，提升了开发者的生产效率。当前的代码搜索系统通常采用“检索-重排序”流水线，其中重排序器专注于建模查询与代码之间的语义相关性。然而，这些重排序器忽略了执行速度、内存使用和可维护性等关键的非功能质量属性，而这些属性对于实际软件开发至关重要。研究表明，开发者期望搜索结果维持高编码标准并满足特定需求（例如资源优化），这凸显了质量感知代码搜索的重要性。实现质量感知的代码搜索面临两大挑战：缺乏用于有效训练的质量标注数据集，以及标准对比学习目标的局限性——它无法捕捉高质量、低质量和无关代码之间的序数关系。尽管对比学习擅长区分相关与无关代码，但其二元目标不支持细微的质量区分。为应对这些挑战，我们提出SynH-Rank，一种质量感知的代码重排序框架，将LLM驱动的多样数据合成与分层排序训练相结合。SynH-Rank采用三级标注方案显式建模层级：高质量相关 > 低质量相关 > 无关。此外，我们引入了一个包含4209对数据的新基准和两个新指标：质量偏好准确率（QPA）用于评估对高质量代码的优先排序，多条件准确率（MCA）用于评估复杂约束下的性能。实验结果表明，SynH-Rank在QPA上比基线模型提高了20.15%，比仅关注相关性的标准对比训练提高了15.80%，同时增强了传统相关性指标和多条件泛化能力。

## Abstract
Code search enhances developer productivity by enabling efficient code reuse. Current code search systems often use a retrieve-then-rerank pipeline, where rerankers focus on modeling semantic relevance between queries and code. However, these rerankers overlook critical non-functional qualities like execution speed, memory usage, and maintainability, which are essential for practical software development. Studies reveal developers expect results to maintain high coding standards and satisfy specific needs, such as resource optimization, highlighting the importance of quality-aware code search.   Achieving quality-aware code search faces two major challenges: the scarcity of quality-annotated datasets for effective training and the limitations of standard contrastive learning objectives, which fail to capture the ordinal relationships among high-quality, low-quality, and irrelevant code. Although contrastive learning excels in distinguishing relevant from irrelevant code, its binary objective does not support nuanced quality distinctions.To address these challenges, we propose SynH-Rank, a quality-aware code reranking framework that combines LLM-driven diverse data synthesis with hierarchical ranking training. SynH-Rank employs a three-level labeling scheme to explicitly model the hierarchy: high-quality relevant > low-quality relevant > irrelevant. Additionally, we introduce a new benchmark with 4,209 pairs and two novel metrics: Quality Preference Accuracy (QPA) for assessing prioritization of high-quality code and Multi-Condition Accuracy (MCA) for evaluating performance under complex constraints.Experimental results show SynH-Rank improves QPA by 20.15\% over backbone models and outperforms standard relevance-only contrastive training by 15.80\%, while simultaneously enhancing traditional relevance metrics and multi-condition generalizability.

- **整体含义**：将质量感知能力引入代码搜索，可以显著提升开发者实际体验和软件工程生命周期。本文首次系统性地解决重排序阶段的质量感知问题，并建立了评估基准与训练框架，推动代码搜索从“语义相关”向“实用相关”演进。

## 2. 方法论：核心思想、关键技术细节、公式与算法流程

- **核心思想**：结合大语言模型（LLM）驱动的多样化数据合成与分层排序训练，显式建模三级标签（高质量相关 > 低质量相关 > 不相关），从而让重排序器同时学习质量偏好和语义相关性。
- **关键技术细节**：
  - **数据合成（Stage 1）**：
    - 针对速度、内存、可维护性三个质量维度，为每个维度设计4条高质量指南和4条低质量指南（共24条）。每条指南对应一个具体的编码策略（如算法复杂度、数据结构选择、代码结构清晰度等）。
    - 对于每个自然语言任务描述 \( q \)，从对应维度的指南组中随机采样一条指南，引导LLM（Qwen3-Coder-30B-A3B-Instruct）生成一个高质量变体 \( c^+ \) 和一个低质量变体 \( c^- \)。
    - 通过遍历所有指南组，单个任务每个维度最多可生成 \( 2K = 8 \) 个代码变体（4个高质量+4个低质量）。生成后经过过滤（去除无效、重复、少于3个唯一候选的任务）。
  - **分层排序训练（Stage 2）**：
    - 为每个查询构建训练列表：一个高质量相关 \( c^+ \)（标签 rel=2）、多个低质量相关 \( c^-_q \)（rel=1）、一个不相关 \( c^-_r \)（rel=0）。
    - 将所有有序对 \( (i,j) \) 其中 \( rel_i > rel_j \) 构成集合 \( S \)。
    - 损失函数采用基于 \( \lvert \Delta \text{nDCG} \rvert \) 加权的 pairwise logistic loss：
      \[
      \mathcal{L}_{\text{LTR}} = \sum_{(i,j) \in S} |\Delta \text{nDCG}_{ij}| \cdot \log\left(1 + \exp(-(s_i - s_j))\right)
      \]
      其中 \( |\Delta \text{nDCG}_{ij}| \) 动态衡量如果交换 \( i,j \) 位置导致的 nDCG 变化，越靠前的误排惩罚越大。
  - **模型架构**：支持三种主流重排序器——交叉编码器（BGE-M3, Jina-v2-base）和生成式重排序器（Qwen3-Reranker）。训练时采用全参数微调，输入长度设为各模型最大上下文窗口。
- **算法流程**（文字说明）：
  1. 从TACO数据集中随机抽取1000个唯一问题，经过去污染过滤（与测试集10-gram重叠去除）。
  2. 对每个问题，使用预定义指南驱动LLM生成4个高质量和4个低质量代码变体，过滤后得到训练集（共13414个代码片段）。
  3. 对于每个查询，构建训练实例：1个高质量相关（正样本）+ 4个低质量相关（负样本）+ 1个随机不相关样本。
  4. 使用分层排序损失微调重排序器，batch size 16，1 epoch，学习率6e-6。

## 3. 实验设计：数据集/场景、Benchmark、对比方法

- **数据集/场景**：
  - 作者构建了 **QualCode** 基准：基于CodeNet（IBM在线判题系统），选取“Accepted”提交，针对速度、内存、可维护性三个维度分别构建正负样本对（速度：最小CPU时间 vs 最大CPU时间且满足2倍差距；内存：类似；可维护性：无代码异味 vs 最多异味，使用SonarQube检测）。共4209对。
  - 构建了 **MC-QualCode** 多条件基准：包含1条件、2条件、3条件子集，每个3000个三元组。正样本满足所有条件，负样本满足N-1个条件（控制变量法）。采用三分位数划分速度/内存标签（前33%为1，后33%为0），可维护性按有无代码异味。
- **评估指标**：
  - 质量偏好：**QPA**（Quality Preference Accuracy，正确排序高质量>低质量的比例）。
  - 多条件：**MCA**（Multi-Condition Accuracy，排序满足所有条件样本高于满足N-1条件样本的比例）。
  - 传统相关性：**MRR@10**、**nDCG@10**（每个查询1个正+99个随机负样本）。
- **对比方法**：
  - **Vanilla Backbone**：直接使用预训练重排序器（不微调）。
  - **标准相关性对比学习（SRCL）**：使用标准InfoNCE损失，仅用相关/不相关二元标签，忽略质量差异。
  - **SynH-Rank**（本文方法）。
- **模型**：BGE-M3、Jina-v2-base、Qwen3-Reranker-0.6B。

## 6. 主要结论与发现

- SynH-Rank在QPA上平均提升20.15%（vs Vanilla）和15.80%（vs SRCL），表明分层训练显著增强了质量辨别能力。
- 在传统相关性指标上，SynH-Rank也普遍优于SRCL（Jina-v2-base MRR@10提升4.64%，Qwen3提升2.49%），证实质量感知训练不会损害语义匹配，反而有助于保持合理排序。
- 在MC-QualCode多条件场景中，SynH-Rank平均提升15.56%（2条件）和12.81%（3条件），展示出对复合约束的良好泛化能力，但性能增益随条件数增加而递减，提示多目标优化仍是挑战。
- 消融实验表明：
  - 移除指南（使用nucleus采样）导致QPA下降6.14%，进一步移除过滤后下降6.7%，证明指南驱动的多样性比数据量更关键。
  - 将分层损失替换为InfoNCE导致QPA下降0.57%，MRR/nDCG下降更显著（~2%），说明InfoNCE因统一惩罚低质量相关样本而损害相关性。

## 7. 优点

- **问题新颖性**：首次系统地将非功能质量（速度、内存、可维护性）纳入代码重排序训练，并建立评估基准与指标（QPA、MCA），填补了领域空白。
- **方法设计巧妙**：
  - 指南驱动合成不仅产生多样性，还提供可解释的变体（如“使用两指针代替暴力枚举”），优于随机采样。
  - 三层标签+ nDCG加权损失自然解决了对比学习的二元局限，并通过动态权重突出顶部排序质量。
  - 训练框架可插拔，支持多种重排序架构（交叉编码器、生成式），且无需重新索引检索库。
- **实验全面**：覆盖了有效性、消融、多条件泛化，并进行了案例分析和多样性定量分析，论证充分。
- **贡献明确**：提供了开源基准（QualCode、MC-QualCode）和可复现的训练流程，有利于后续研究。

## 8. 不足与局限

- **实验覆盖局限**：
  - 仅评估了Python语言，未验证Java、JavaScript等其他语言的有效性。Python的动态类型和语法特性可能导致指南适用性受限。
  - 仅关注三个质量维度（速度、内存、可维护性），未涵盖安全性、可移植性、可测试性等常见非功能需求。
  - 测试集仅来自CodeNet（在线判题系统），代码风格偏向竞赛型，与真实工业级代码存在差异。
- **模型偏差风险**：
  - 数据合成仅使用Qwen3-Coder单一模型，可能引入该模型的特定偏见（如倾向于生成某种风格的代码）。文中也承认这一点，并建议未来使用多种LLM。
  - 可维护性评估依赖SonarQube静态分析，其检测规则可能无法覆盖所有反模式，且阈值设置（无smell vs 最多smell）较粗粒度。
- **方法限制**：
  - 多条件场景下性能增益随条件数增加而递减，说明方法在处理复杂约束时仍有瓶颈。
  - SynH-Rank的训练需要针对每个查询合成多个变体，计算成本较高（涉及LLM生成和过滤），可能不适合极大规模检索场景的在线训练。
  - 在BGE-M3（弱基础模型）上，SynH-Rank的传统相关性指标低于SRCL，说明模型能力不足时，同时优化质量和相关性的多目标学习可能造成冲突。
- **公平性考量**：仅与自身基线对比，未与其他质量感知检索方法（如CoQuIR的问题诊断、EffiLearner的生成优化）直接对比（因为任务设置不同），但可视为领域特异性。
