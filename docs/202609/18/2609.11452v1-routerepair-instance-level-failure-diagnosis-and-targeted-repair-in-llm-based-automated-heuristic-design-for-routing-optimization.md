## 摘要
高效的路径优化对货运、城市物流和共享出行至关重要，这些场景通常需要在有限计算预算下获得高质量启发式方法。近期基于大语言模型（LLM）的自动启发式设计方法能够生成有效的路径规则，但聚合评估可能掩盖其在特定实例结构上的反复失败。为解决这一局限，本研究提出RouteRepair，它从实例级性能中诊断父代特定的弱点，并对相应启发式组件进行定向修改，同时保护已表现良好的行为。该方法结合路径证据、求解器行为和程序上下文来定义有界修复目标，并通过匹配的父代-子代评估对每次干预进行验证，考察失败恢复与附带退化。在旅行商问题（TSP）和带容量约束的车辆路径问题（CVRP）上的实验涵盖构造式搜索、引导局部搜索和蚁群优化。RouteRepair-GLS将TSP的平均最优性差距从1.7476%降至0.7587%，而构造式CVRP启发式相较于节约启发式将平均路径成本降低1.91%；生成的ACO先验也优于匹配的手工设计先验。这些结果表明，故障感知且受证据约束的改进能够提升困难实例上的路径启发式，同时保持其已能良好求解实例的性能。

## Abstract
Efficient routing optimization is essential to freight transportation, urban logistics, and shared mobility, where high-quality heuristics are often required under limited computational budgets. Recent large language model (LLM)-based automated heuristic design methods can generate effective routing rules, but aggregate evaluation may mask recurrent failures on particular instance structures. To address this limitation, this study develops RouteRepair, which diagnoses parent-specific weaknesses from instance-level performance and applies targeted modifications to the corresponding heuristic components while protecting behavior that already performs well. Routing evidence, solver behavior, and program context are combined to define bounded repair objectives, and each intervention is validated through matched parent-child evaluation of failure recovery and collateral degradation. Experiments on the traveling salesman problem (TSP) and capacitated vehicle routing problem (CVRP) span constructive search, guided local search, and ant colony optimization. RouteRepair-GLS reduces the mean TSP optimality gap from 1.7476% to 0.7587%, while the constructive CVRP heuristic lowers average route cost by 1.91% relative to the savings heuristic; the generated ACO priors also outperform matched hand-designed priors. These results show that failure-aware, evidence-constrained refinement can improve routing heuristics on difficult instances while preserving performance on cases they already solve well.

## 2. 方法论

### 2.1 总体框架：嵌套搜索

- **外层进化循环**（沿用 FunSearch/EoH/ReEvo 思路）：生成可执行路径启发式 → 过滤非法程序 → 在固定 TSP/CVRP 求解器骨架内评估 → 以聚合路径质量做候选选择，但**完整保留实例级性能画像**；同时保留常规变异与可选重组以探索其他启发式结构。
- **内层诊断-修复循环**：只针对"整体强但在特定实例上反复弱"的父代。构造失败/优势/保护集合 → 失败诊断专家产出结构化修复假设 → 内部风险评审 → 冻结修复简报 → 定向修复专家只改指定打分规则或边先验函数 → **父子匹配评估**（相同实例、随机种子、求解器设置、计算预算）→ 结果写入记忆。

### 2.2 问题设定与关键公式（文字说明）

- 启发式表示为**嵌入固定求解器的可执行组件**：求解器 $S_k$ 负责可行性、状态转移、邻域操作与终止，LLM 只提供指定接口函数。对实例 $x_i$ 得到可行解 $y_i(h)$ 与目标值 $z_i(h)=f_k(x_i,y_i(h))$（所有目标均为最小化）。
- **实例级归一化损失** $r_i(h)=\frac{z_i(h)-z_i^{ref}}{\max(z_i^{ref},\varepsilon)}$，其中参考值可为最优解、已知最优（BKS）或协议固定值，$\varepsilon>0$ 防止除零；$r_i=0$ 表示达到参考值。
- **同时保留损失向量与均值**：$r(h)=(r_1,\dots,r_N)$ 用于定位父代特定失败，$\bar r(h)$ 用于种群排序。
- **父代特定案例构造**：按适配器特定的严重度指标在**每个规模组内**排序并归一化秩 $u_p(h_p)$，秩 1 表示该规模内最差；按预设比例取 Top 尾部为**失败集 $F(h_p)$**、Bottom 部分为**优势集 $S(h_p)$**；**保护集 $A(h_p)=\mathcal D\setminus F(h_p)$** 覆盖所有非失败实例，仅用于外部接受性检验（比展示给 LLM 的优势子集更大）。若存在匹配基线，可加入对比证据（如构造式 TSP 先标出父代输给最近邻的实例，再用高差距实例填满失败槽）。
- **诊断证据**（表 2）：TSP 类含实例结构（规模、距离分布、最近邻间距、局部/全局间距比、密度、长宽比、节点分离度）与解行为（路径差距、长边比例、交叉模式、边选择偏好、停滞趋势、打分/先验分布）；CVRP 类额外含需求结构（需求变异、需求-容量比、空间-需求相关性）与车辆利用率、路径/载重方差、碎片化、晚到客户模式等。所有描述子均为评估器已有数据的确定性摘要。

### 2.3 双专家与结构化诊断报告

- **失败诊断专家**：输入父代函数、失败/优势案例、表 2 证据、当前排名与匹配基线对比。**不生成代码**，只把反复出现的路径结果与可编辑组件关联，给出**有界修复目标**；诊断被视为"可检验的程序级假设"而非既定因果。
- **结构化诊断报告**（诊断与修复之间的契约）：固定字段 `failure_evidence`、`weak_behavior`、`root_cause`、`repair_objective`、`repair_risk`，以及 1–3 个互不重复的 `repair_families`（各含目标失败模式与代码改动焦点），避免泛泛评论或反复调系数。
- **内部风险评审**：仍属诊断专家（不构成第三个代码生成专家），核查诊断与证据一致性、识别需保留行为与过拟合风险、去重修复方向，产出简明修复指令；**诊断与评审随后被冻结**，防止修复专家在看到候选修改后重新定义弱点。
- **定向修复专家**：接收冻结简报、单一修复族、父代代码、精简案例摘要、精英上下文与少量相关记忆记录；必须保持表 1 的函数签名，做**局部或有界结构性改动**。GLS/构造式适配器返回单一有限标量打分函数；ACO 适配器返回与距离矩阵同形状的确定性有限边先验矩阵。信息素动态、路径构造、可行性检查与不可用动态状态均在可编辑区域之外。

### 2.4 保持优势的匹配验证与结果感知记忆

- **失败集平均损失下降** $G_F$：子代相对父代在失败集上的归一化损失平均减少量，正值表示改善被诊断的目标案例。
- **恢复率** $R_F$：相对父代初始失败严重度的恢复比例，便于跨不同初始严重度的父代比较。
- **附带退化** $C_A$：在完整保护集上的**单侧**平均退化 $\frac{1}{|A|}\sum \max(0, r_i(h_c)-r_i(h_p))$——部分保护案例的改善**不允许抵消**其他案例的新增损害。
- **验证条件**：仅当 $R_F\ge\tau_F$ 且 $C_A\le\tau_A$ 时，子代才被计为"成功的定向修复"。**修复成功与进入种群被有意分离**：子代可能因聚合折衷而对进化搜索有用，但未通过恢复/附带损害条件就不算已验证修复。
- **结果感知记忆**：每次干预连同诊断、修复策略、父子结果、恢复率、附带退化与验证结论一并存储，后续提示检索的是**实测结果**而非未经验证的建议。
