## 摘要
高效的路径优化对货运运输、城市物流和共享出行至关重要，在这些场景中，通常需要在有限的计算预算下获得高质量的启发式方法。近期基于大语言模型（LLM）的自动启发式设计方法能够生成有效的路径规则，但聚合评估可能掩盖其在特定实例结构上反复出现的失败。为解决这一局限，本研究开发了RouteRepair，它从实例级性能中诊断父代特定的弱点，并对相应启发式组件进行针对性修改，同时保护已经表现良好的行为。将路径证据、求解器行为和程序上下文相结合，以定义有界修复目标，并通过匹配的父代-子代评估来验证每次干预的失败恢复情况和附带退化情况。在旅行商问题（TSP）和带容量约束的车辆路径问题（CVRP）上的实验涵盖构造式搜索、引导局部搜索和蚁群优化。RouteRepair-GLS将TSP平均最优性差距从1.7476%降至0.7587%，而构造式CVRP启发式相对于节约启发式将平均路径成本降低了1.91%；生成的ACO先验也优于匹配的人工设计先验。这些结果表明，失败感知、证据约束的精炼能够改善困难实例上的路径启发式，同时保持在已能良好求解的实例上的性能。

## Abstract
Efficient routing optimization is essential to freight transportation, urban logistics, and shared mobility, where high-quality heuristics are often required under limited computational budgets. Recent large language model (LLM)-based automated heuristic design methods can generate effective routing rules, but aggregate evaluation may mask recurrent failures on particular instance structures. To address this limitation, this study develops RouteRepair, which diagnoses parent-specific weaknesses from instance-level performance and applies targeted modifications to the corresponding heuristic components while protecting behavior that already performs well. Routing evidence, solver behavior, and program context are combined to define bounded repair objectives, and each intervention is validated through matched parent-child evaluation of failure recovery and collateral degradation. Experiments on the traveling salesman problem (TSP) and capacitated vehicle routing problem (CVRP) span constructive search, guided local search, and ant colony optimization. RouteRepair-GLS reduces the mean TSP optimality gap from 1.7476% to 0.7587%, while the constructive CVRP heuristic lowers average route cost by 1.91% relative to the savings heuristic; the generated ACO priors also outperform matched hand-designed priors. These results show that failure-aware, evidence-constrained refinement can improve routing heuristics on difficult instances while preserving performance on cases they already solve well.

## 1. 核心问题与研究动机

- **应用背景**：路径优化（routing optimization）是货运配送、城市物流、共享出行与新兴自动配送服务的核心问题，TSP 与 CVRP 是两个基础模型。精确算法随客户数与约束增长而负担剧增，因此有限预算下仍需依赖构造式启发式、局部搜索与种群式元启发式。
- **关键瓶颈**：启发式方法的效力往往取决于紧凑的启发式组件（如“下一个选哪个节点”“给哪条边加罚”“边先验如何设定”）。这些组件难以设计，因为设计者需选择有信息量的状态变量、组合竞争性准则，并检验规则在密度、需求分散度、容量、规模变化下是否仍然有效。
- **AHD 的现状**：自动启发式设计（AHD）把该任务重构为“对规则/算子/可执行程序的搜索”，LLM（FunSearch、EoH、ReEvo 等）提供了更广的程序先验与语义化代码变异能力。
- **核心问题**：绝大多数 LLM-based AHD 方法仍以**平均目标值、平均最优性差距等标量适应度**排序候选。这种聚合评估**掩盖了**一个关键区别——启发式究竟是“整体平庸”，还是“在大多数实例上很强、但在某一结构一致的子集上反复失败”。
- **研究缺口**：已有的互补启发式集合、状态依赖选择、跨尺度训练、鲁棒性基准等工作，并未直接回答“当一个有竞争力的路由启发式在特定空间/距离/需求-容量模式上反复失败时，应当如何修改其逻辑”。
- **整体含义**：RouteRepair 主张把 LLM-based AHD 从“平均适应度驱动的替换”转向“实例级修复”——在**不丢弃**整体上仍有竞争力的父代启发式的前提下，纠正其反复出现的路由失败。

## 2. 方法论

### 2.1 核心思想

- 采用**嵌套搜索框架**：外层进化搜索负责广泛发现（生成、校验、评估候选程序，按聚合路线质量选择），内层诊断-修复过程针对“整体强但局部不一致”的父代。
- 采用**固定骨架表示（fixed-backbone）**：LLM 只修改被指定的启发式接口，可行性、状态转移、邻域操作、终止条件全部由外层求解器固定控制，从而使父代-子代比较具有意义。
- 保留**完整实例级性能画像**，而非只保留均值。

### 2.2 形式化定义

- 第 i 个实例上，启发式 h 在固定求解器 S_k 下产生可行解 y_i(h) 与目标值 z_i(h)。
- **归一化实例级损失**：r_i(h) = (z_i(h) − z_i^ref) / max(z_i^ref, ε)，其中 z_i^ref 为最优值、已知最好值或协议固定值，ε>0 防止除零；目标为最小化，r_i=0 表示达到参考值。
- 同时保留损失向量 **r(h) = (r_1,…,r_N)**（用于定位父代失败）与其算术平均 **r̄(h)**（用于种群排序）。

### 2.3 五类路由适配器（可编辑组件）

| 适配器 | 固定骨架 | LLM 生成函数 |
|---|---|---|
| TSP-GLS | 引导局部搜索 | score_edge_for_penalty(...) 边罚分评分 |
| Constructive TSP | 确定性巡游构造器 | score_next_node(...) 下一节点评分 |
| Constructive CVRP | 容量可行构造器 | score_next_customer(...) 下一客户评分 |
| TSP-ACO | 固定 ACO | score_tsp_aco_edges(...) 返回 n×n 边先验矩阵 |
| CVRP-ACO | 固定可行 ACO | score_cvrp_aco_edges(...) 返回 n×n 边先验矩阵 |

- 构造式适配器中，固定骨架先给出可行候选集（CVRP 会先剔除容量不可行的客户），生成函数只影响偏好、不影响可行性。
- ACO 适配器把输出从标量改为**静态边先验矩阵** H_h，经验证形状与数值有效性后转为非负期望度矩阵并将对角线置零；固定 ACO 按 τ_ij(t)·[η_h,ij]^β 形式与信息素结合（α、β 固定）。生成先验**不能**改变信息素蒸发、精英沉积、指数、蚂蚁数、迭代数或随机种子；CVRP-ACO 中访问状态与剩余容量对生成函数隐藏。

### 2.4 父代特定案例集构造

- 不依赖“全局困难实例清单”，而是按**适配器特定的严重度度量**对父代自身结果排序，并在每个规模组内归一化秩：u_p(x_i) = (rank_g(i;h_p) − 1)/(m_g(i) − 1)，秩 1 表示该规模组内父代表现最差。
- **失败集 F(h_p)**：按预设失败比例 q_f 取排序最差（Top）的实例。
- **强度集 S(h_p)**：从同一画像中表现最好部分取代表实例，作为需保留行为的紧凑描述。
- **保护集 A(h_p) = D \ F(h_p)**：所有非失败实例，用于正式评估附带损伤；它比展示给 LLM 的强度子集更广。
- 若有匹配基线，可加入**对比证据**（例如构造式 TSP 先挑出父代输给最近邻的实例，再用高差距实例填满失败槽位）。
- **诊断证据包**（表 2）包含三类确定性描述符：
  - 实例结构：规模、距离分布、最近邻间距、局部/全局间距比、密度、长宽比、节点分离度（CVRP 另加客户分布、仓库径向特征、需求变异、需求-容量比、需求空间相关性）；
  - 解行为：巡游差距、长边比例、交叉模式、边选择偏好、停滞趋势、车辆利用率、路线/载荷方差、碎片化、晚客户模式；
  - 生成评分函数或边先验的统计分布。

### 2.5 故障诊断专家与定向修复专家

- **Failure Diagnosis Expert**：输入父代函数、失败/强度案例、表 2 证据、当前排名、可选匹配基线对比；**不生成代码**，只把反复出现的路由结果与可编辑组件关联，给出**有界修复目标**。提示词由共享专家指令 + 适配器特定契约（函数签名、固定求解器边界、目标、允许输入、失败词汇表）组成。
- **结构化诊断报告**（诊断与修复之间的契约）固定字段：`failure_evidence`、`weak_behavior`、`root_cause`、`repair_objective`、`repair_risk`，以及 1–3 个互异的 `repair_families`（每个含目标失败模式与代码修改重点）。固定 schema 把实例级证据转为**有界修复方向**，而非泛泛评论或反复调系数。
- **内部风险审查**：在代码生成前，依据所引证据复核诊断、识别需保留行为与过拟合风险、剔除重复修复方向、产出简洁指令；该审查仍属诊断专家，**不构成第三个生成代码的专家**。诊断与审查随后**冻结**，防止修复专家在看到候选修改后重新定义弱点。
- **Targeted Repair Expert**：接收冻结简报、单一修复族、父代代码、紧凑案例摘要、精英上下文与少量相关记忆记录；必须保持函数签名，只做与诊断机制相关的**局部或有界结构修改**。GLS/构造式返回单个有限标量评分函数；ACO 返回与距离矩阵同形状的确定性有限边先验矩阵。信息素动力学、路线构造、可行性检查与不可用动态状态均不可编辑。

### 2.6 保强匹配验证与结果感知记忆

- 子代通过语法、接口、数值校验门后，与父代在**匹配条件**下比较（同实例、同随机种子、同求解器设置、同计算预算）。
- **失败集上的平均损失下降**：G_F(h_p,h_c) = (1/|F|)Σ_{x_i∈F} [r_i(h_p) − r_i(h_c)]，正值表示改善。
- **恢复率**：R_F = G_F / [(1/|F|)Σ_{x_i∈F} max(r_i(h_p), ε)]，用于跨不同初始严重度的父代比较。
- **附带退化（单侧）**：C_A = (1/|A|)Σ_{x_i∈A} max(0, r_i(h_c) − r_i(h_p))，即保护集上新建损伤不被其他实例的改善所抵消。
- **成功判定**：仅当 R_F ≥ τ_F 且 C_A ≤ τ_A 时记为一次成功的定向修复。
- **关键设计**：定向修复成功与“进入种群”**刻意分离**——子代可因聚合权衡仍对进化搜索有用，但若未通过恢复/附带损伤条件则不计为已验证修复。
- **结果感知记忆**：每次干预存储诊断、修复策略、父子结果、恢复率、附带退化与验证结果；后续提示检索相关的成功与失败案例，使记忆反映**实测结果**而非未经验证的建议。

## 3. 实验设计

### 3.1 场景与数据集

- **问题**：TSP 与 CVRP，共 **5 个适配器**（TSP-GLS、Constructive TSP、TSP-ACO、Constructive CVRP、CVRP-ACO），覆盖构造式搜索、引导局部搜索与蚁群优化。
- **规模**：TSP20/50/100/200（TSP-ACO 另含 2 个 TSP500 迁移实例）；CVRP50/100/200/500（CVRP-ACO 另含 CVRP1000 泛化）。
- **训练/测试规模**：构造式 TSP 与 CVRP 搜索使用 128 个训练实例、25 轮进化、8 个初始候选、每轮最多 5 个修复候选。CVRP 留出集在 CVRP50/100/200/500 各 64 个实例；TSP-ACO 留出集为 15 个 TSP20、TSP50、TSP100、TSP200 各 4 实例加 2 个 TSP500。
- **迁移/泛化基准**：完整 **TSPLIB 30 实例池**（不做重训练）与完整 **CVRPLIB** 池。
- **TSP-ACO 设置**：24 只蚂蚁、40 次迭代、种子 0/1/2。

### 3.2 对比方法

- **TSP-GLS**：Standard GLS、Low-penalty GLS、EBGLS-lite（Shi et al. 2018 组件级适配）、GNNGLS-lite（Hudson et al. 2022）、EoH、PoH；以及完整 ReEvo 运行的**预算感知对比**。
- **构造式 TSP**：Nearest Neighbor、Cheapest Insertion、Farthest Insertion，以及各自与**同一 2-opt** 后处理（用于隔离初始巡游质量）。
- **TSP-ACO**：ReEvo、inverse-distance prior、nearest-rank prior（全部在同一固定 ACO 骨架下匹配比较）。
- **构造式 CVRP**：savings heuristic、EoH-adapted guide、ReEvo-adapted guide、最佳初始 LLM 程序；OR-Tools Routing GLS 仅作外部求解器参考（因其引入匹配评分接口之外的邻域搜索）。
- **CVRP-ACO**：容量感知先验（CVRP50–500）、inverse-distance 先验（CVRP1000）。
- **消融**：Full RouteRepair、w/o expert-role separation、w/o memory、w/o repair、w/o failure attribution（同测试实例、同随机种子、同评估设置，仅移除对应组件）。

### 3.3 公平性设计

- 父子比较固定实例、求解器种子、配置与评估预算；TSP-GLS 与构造式 TSP 使用**共同求解器骨架**，EBGLS/GNNGLS/PoH 标注为组件级迁移（lite/adapted）而非完整系统复现。
- 所有构造式方法施加**同一 2-opt 过程**，避免方法特定局部搜索带来的混杂。
- TSPLIB 迁移**保留全部 30 个实例**，包括 RouteRepair 不占优的案例。
