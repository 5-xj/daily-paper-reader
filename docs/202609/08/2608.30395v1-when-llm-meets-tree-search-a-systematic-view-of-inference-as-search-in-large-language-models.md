## 摘要
随着预训练缩放定律接近饱和，测试时缩放（TTS）已成为一种重要方向，通过将推理时间计算分配给固定先验模型来提升推理能力。从高层次看，TTS将推理重新定义为对部分推理状态空间的搜索。虽然思维链（CoT）暴露了中间步骤，但常见实例化依赖于单轨迹解码，限制了从早期错误中的恢复和探索。本综述系统化了基于树搜索的推理的最新进展，将推理视为实例特定的优化而非解码。我们追溯了从无信息搜索到蒙特卡洛树搜索（MCTS）的演变，强调了基于采样的控制如何支持原则性的探索-利用权衡。为了统一碎片化的文献，我们引入了一个统一设计空间，涵盖搜索拓扑、评估信号和控制动态，并提倡一种标准化的计算报告抽象，使计算-准确性权衡变得明确且可比较。

## Abstract
As pretraining scaling laws approach saturation, Test-Time Scaling (TTS) has emerged as an important direction for improving reasoning by allocating inference-time compute to a fixed model prior. Viewed at a high level, TTS reframes inference as search over a space of partial reasoning states. While Chain-of-Thought (CoT) exposes intermediate steps, common instantiations rely on single-trajectory decoding, limiting recovery from early errors and exploration. This survey systematizes recent progress in tree-search-based reasoning, viewing inference as instance-specific optimization rather than decoding. We trace the evolution from uninformed search to Monte Carlo Tree Search (MCTS), highlighting how sampling-based control supports principled exploration-exploitation trade-offs. To unify a fragmented literature, we introduce a Unified Design Space spanning search topology, evaluation signals, and control dynamics, and advocate a standardized compute-reporting abstraction to make compute-accuracy trade-offs explicit and comparable.

## 2. 方法论：核心思想与关键技术

### 2.1 统一形式化表示

- 将基于搜索的推理分解为三类组件：**搜索拓扑（Search Topology）、评估信号（Evaluation Signal）、控制动态（Control Dynamics）**。
- 在确定性规划假设下（每个推理动作 `a_i` 唯一确定下一状态 `s_{i+1}`），搜索目标是找到最优推理轨迹 `p* = [s_1, ..., s_n]`。

### 2.2 搜索三要素分类

| 组件 | 关键设计选择 |
|---|---|
| **搜索拓扑** | 节点粒度：轨迹级节点（如 ReST-MCTS*）、状态-动作节点（如 RAP、AlphaLLM）、终端状态节点（如 LLaMA-Berry、MCTSr） |
| **评估信号** | 过程奖励（PRM）vs 结局奖励（ORM）；外部判别器 vs 策略模型自评估；单信号 vs 多信号复合（如 AlphaLLM 的三重加权） |
| **控制动态** | 选择/扩展/回传的算法变体（P-UCB、critique-and-rewrite 扩展、max/avg/min 混合回传规则等） |

### 2.3 搜索奖励与 RL 奖励的概念区分

- **RL 奖励**：通过梯度更新内化到模型参数，形成**持久性策略改变**；
- **搜索奖励**：作为**外部、瞬时**信号，仅指导当前实例的规划，不改变参数。
- 两者并非竞争而是互补，可形式化为双层优化框架，用于解释混合 MCTS-训练方法（如搜索生成轨迹蒸馏为策略数据）。

### 2.4 搜索算法谱系

- 从**无信息搜索**（BFS/DFS/UCS）到**有信息搜索**（A*、Beam Search、ToT），再到**MCTS**：MCTS 通过采样统计避免显式启发式设计，在奖励嘈杂/稀疏/仅终端可得的场景中更具适应性。
- 对启发式搜索做补充分析：将 ToT 等归为"直接状态评估"范式，将 Q*、ToolChain* 归为"A* 复合代价函数"范式，其 g(n) 与 h(n) 可由自一致性频率、记忆相似度、LLM 想象评分等构成。

### 2.5 核心公式摘要

- **UCT/PUCT 选择规则**：
  ```
  a* = argmax_a [ Q(s,a) + c · π(a|p,Q) · √n_i / (1 + n_j) ]
  ```
- **计算成本模型（SCRP 提议）**：
  ```
  C_total(x) ≈ 2·P_policy·T_policy(x) + 2·P_eval·T_eval(x) + C_verify(x)
  ```
  其中 P 为参数量，T 为 token 数，该公式用于实现跨硬件、跨方法的近似可比。
- **AlphaLLM 多批评家节点价值**：
  ```
  Q_i ← β_1·V_i + β_2·R_PRM_i + β_3·R_ORM_i
  ```

### 2.6 标准化计算报告协议（SCRP）

- 将推理资源分解为预算向量 `B = (C_policy, C_eval, C_verify, T_wall)`；
- 推荐汇报 **Budgeted Accuracy（Pass@FLOPs）**、**Tokens-per-Solved（TpS）**、**Parallelism Efficiency**；
- 该协议是描述性而非规范性：不排名、不定义最优性，只使计算-精度权衡显式化。

## 6. 主要结论与发现

### 6.1 搜索的有效性条件

- 树搜索在**可验证任务**（数学推理、程序合成）中常能带来可观增益（文中汇集结果常见报告 10–40% 的提升），原因在于数值检查器/单元测试提供了稳定监督。
- 在**开放生成任务**中，搜索相对强解码基线的增益通常边际化。

### 6.2 MCTS 与启发式搜索的取舍

- LLM 生成的启发式（如 ToT）在延迟预算严格或中间信号可靠时表现好；MCTS 则通过经验统计积累，在**稀疏奖励、中间步骤具有欺骗性**的长程推理中更稳健。

### 6.3 两大核心瓶颈

1. **计算开销**：搜索比贪心解码高一个量级以上；强模型在简单查询上"过度思考"（overthinking）浪费算力；树搜索的结构性限制降低并行度，影响自博弈蒸馏循环效率。
2. **奖励质量**：PRM 训练依赖昂贵且难扩展的人工标注；现有自动方法多局限于数学等窄领域；不完美的奖励可误导搜索，甚至引发**逆缩放（inverse scaling）**——rollout 越多精度反而下降。

### 6.4 未来方向

- 自适应/选择性激活搜索（动态资源分配 + 激进剪枝）；
- 更可扩展的高保真过程奖励生成（含符号约束、正则语言限制、自动规范学习的补充路径）；
- 缩短推理轨迹本身（如结合 Chain-of-Draft 的 DRAFT-RL 思路）而非仅裁剪搜索树；
- 将搜索行为内部化到模型参数的自博弈循环，实现从测试时优化到持久性参数知识的转化。
