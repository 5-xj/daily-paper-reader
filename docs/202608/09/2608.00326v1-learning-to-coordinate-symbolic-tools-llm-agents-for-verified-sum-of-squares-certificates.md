## 摘要
工具调用使大型语言模型（LLM）能够在问题求解过程中调用外部计算，这在包括AI for Mathematics在内的多个领域中是一项有用的能力。我们通过加权平方和（SOS）分解来研究这一设置，这是一种可机器检查的证明多项式非负性及多项式不等式的方法。候选分解可以被精确检查，但找到一个分解需要在非唯一的重新分组中进行选择，并协调多个符号变换。我们开发了一个智能体，它结合了代数任务训练、符号工具和基于验证器的优化来完成这项任务。我们不仅针对复合SOS任务进行训练，还构建了135万个涵盖八个支持多项式任务以及加权SOS分解的合成示例。我们首先应用监督微调（SFT）来处理直接代数问题和模拟符号轨迹，然后使用带有任务特定符号奖励的Group Relative Policy Optimization（GRPO）。SFT语料库不包含原生工具调用消息；在评估时，智能体使用原生SymPy调用来进行展开、收集、重排序和因式分解。每个最终的SOS答案都通过精确展开和系数比较进行检查。在来自同一生成器的保留合成问题上，完整的SFT+GRPO+工具系统是四种评估配置中最强的，在加权SOS上达到了78.96%的验证成功率，而具有相同工具的基础模型为44.73%，在九个多项式任务上的宏平均准确率为91.75%。在这个受控设置中，我们的工作提供了一个结合领域特定技能训练、可执行工具和验证器反馈的案例研究，并可能为其他具有可精确检查输出的领域中工具调用智能体的设计提供参考。

## Abstract
Tool calling allows large language models (LLMs) to invoke external computation during problem solving, a useful capability in various fields including AI for mathematics. We study this setting through weighted sum-of-squares (SOS) decomposition, a machine-checkable route to proving polynomial nonnegativity and hence polynomial inequalities. A candidate decomposition can be checked exactly, but finding one requires choosing among non-unique regroupings and coordinating multiple symbolic transformations. We develop an agent that combines algebraic task training, symbolic tools, and verifier-grounded optimization for this task. Rather than training only on the composite SOS task, we construct 1.35 million synthetic examples covering eight supporting polynomial tasks together with weighted-SOS decomposition. We first apply supervised fine-tuning (SFT) to direct algebra problems and simulated symbolic traces, and then use Group Relative Policy Optimization (GRPO) with task-specific symbolic rewards. The SFT corpus contains no native tool-calling messages; at evaluation, the agent uses native SymPy calls for expansion, collection, reordering, and factorization. Every final SOS answer is checked by exact expansion and coefficient comparison. On held-out, same-generator synthetic problems, the full SFT+GRPO+tools system is the strongest of four evaluated configurations, reaching 78.96% verified success on weighted SOS, compared with 44.73% for the base model with the same tools, and 91.75% macro accuracy across nine polynomial tasks. Within this controlled setting, our work provides a case study of combining domain-specific skill training, executable tools, and verifier feedback, and may inform the design of tool-calling agents in other domains with exactly checkable outputs.

## 1. 核心问题与研究动机

- **背景**：工具调用（tool calling）让 LLM 能借助外部计算完成多步推理；在 AI for Mathematics 中，许多任务的输出“容易验证、但难以搜索”。作者选择**加权平方和（weighted SOS）分解**作为受控研究场景：候选证书可以被精确展开验证，但发现证书需要在非唯一的分组方式中做策略性选择，并协调多个符号变换。
- **核心问题**：能否通过“代数接地（algebra-grounded）的后训练”，让 LLM 不只是执行孤立的代数变换，而是学会在**多步符号搜索中协调多个精确符号工具**？
- **研究定位**：该工作不是为了在不等式证明上取得 SOTA，而是把加权 SOS 当作一个“输出可被机器精确检查”的环境，研究工具调用智能体的顺序决策与训练方式。

## 2. 方法论

### 整体思想
采用“**合成课程 + 两阶段后训练 + 原生工具部署 + 精确验证器**”的流程：

- 构建 9 类多项式任务、共 135 万条合成样本；
- 先做助手令牌级 QLoRA SFT；
- 再用带“任务特定符号奖励”的 GRPO 强化学习；
- 评估时让智能体通过原生 SymPy 接口调用四个符号函数；
- 最终证书由精确展开与系数比对验证器判定。

### 训练课程（9 类任务）
- **4 个局部操作任务**：字典序项排序、收集（collection）、展开（expansion）、因式分解（factorization）。
- **4 个结构代数任务**：Horner 形式、对称多项式约化、商/余式计算、扩展欧几里得算法（Bézout 恒等式）。
- **1 个复合目标任务**：加权 SOS 证书搜索。
- 每个任务生成 150,000 条样本（验证集占 5%），共 1,350,000 条；训练集为 1,282,500 条。

### 加权 SOS 问题的形式
目标证书形如：
```
f = Σ_j c_j · p_j^2,   c_j ∈ Q_{>0}
```
验证器要求：结构上每个加项为“平方乘正有理系数”，且精确满足：
```
expand(f - Σ_j c_j p_j^2) = 0
```
验证器接受任意有效分解，不要求与生成时隐藏的分解一致。

### SFT 阶段
- 基座模型：`Phi-4-reasoning-plus`；
- 4-bit QLoRA（rank=32, scale=16, dropout=0.05）；
- 直接任务使用“问题—答案”记录；SOS 任务使用**模拟的 Python 风格符号轨迹**（包含重试和错误观察），但**不包含原生 function-call 消息**；
- 仅计算 assistant token 的交叉熵损失；system/user token 作为上下文但被 mask；
- 1 个 epoch，22,731 个优化步。

### GRPO 阶段
- 从 SFT 模型初始化，继续优化适配器；
- 使用任务特定的**精确符号奖励**而非字符串匹配：
  - 格式门控：若缺少答案包装则奖励为 -1；
  - 任务分数（0~1）基于精确多项式相等、正规形式条件、Bézout 恒等式、SOS 结构门控与系数残差等；
  - 例如 SOS 奖励综合结构门控（正有理数权重 + 平方结构）与系数残差；
  - 另有轨迹塑形奖励：奖励有效、可执行、不重复的工具调用，惩罚重复调用与过长轨迹，给“验证通过”最高增量。
- 全局 prompt batch = 64，每个 prompt 生成 8 条响应，20,039 个优化步。

### 原生工具部署
- 评估时（仅 Base+Tools 和 Full 配置）提供 4 个 SymPy 后端函数：`expand_polynomial`、`collect_terms`、`reorder_polynomial`、`factorize_polynomial`；
- 预算限制：最多 10 次工具调用、3 次分解尝试、单次调用 5 秒、每 episode 60 秒；
- 终端验证器独立于模型与工具，判定最终证书是否通过。

- **加权 SOS（原生工具系统）**：

  - SFT：51.82%；
  - Base+Tools：44.73%；

- **相对提升**：SFT 比 Base 高 44.19 个百分点；Base+Tools 比 Base 高 37.10 个百分点；Full 比 Base+Tools 高 34.23 个百分点。

## 7. 优点

- **任务设计巧妙**：加权 SOS 是“输出易验证、搜索难”的理想代理任务；反向构造保证证书存在，但不暴露隐藏分解，避免模型记住单一答案。
- **验证器稳健**：接受任意有效证书，不只匹配生成时的分解；用精确系数展开判定，避免文本相似度或表面格式的假阳性。
- **训练数据规模化与结构化**：135 万合成样本、9 类任务把复合 SOS 搜索分解为可学习的局部技能与结构技能，强调“技能训练而非接口训练”。
- **训练—部署边界清晰**：SFT 语料不包含原生 tool-call 消息；GRPO 用于响应级优化；原生工具调用只在最终 SOS 评估中出现；责任分工（模型、harness、验证器）在附录中明确列出。
- **实验公平性良好**：四配置共享同一工具接口、同一解码设置、同一预算；对有限测试集给出了 Wilson 区间；对训练成本有详细记录。
- **诚实且克制的表述**：作者明确区分“完整系统结果”与“组件归因”，不把描述性分组当作消融；多处强调局限，避免过度宣称。

## 8. 不足与局限

- **泛化范围有限**：仅限 1–3 变量、小规模合成多项式、同一生成器族；不覆盖自然不等式、更大多项式或非 SOS 判定。
- **组件无法隔离**：缺少 SFT+Tools 与 GRPO-without-tools 配置，无法判断 GRPO、工具、SFT 各自的独立贡献，也无法判断模拟轨迹到原生调用的表示变化是否关键。
- **单一骨干与单次运行**：只使用 Phi-4-reasoning-plus，一个 SFT 检查点与一个 GRPO 检查点，没有多种子、多次运行或跨模型迁移证据。
- **训练目标窄**：仅覆盖加权 SOS（A={∅}），不涵盖 Putinar/Schmüdgen/Stengle 等约束证书情境；抽象或“放弃”被计为搜索失败，不提供可靠的负向判定能力。
- **保留检查证据较弱**：AIME-90 样本量小（90 题），avg@16 只是平均样本正确率，不是 pass@16 或多数投票；不能作为广泛保留或迁移的强证据。
- **合成分布偏差风险**：训练与测试共享生成器家族，可能使模型偏向特定系数/次数/项数分布，在真实数学问题上未必可用。
