## 摘要
基于大语言模型的自动启发式设计（LLM-AHD）在发现组合优化问题的有效启发式方面展现出强大潜力。然而，现有方法主要优化单一启发式，而实际优化框架往往依赖多个交互组件。直接扩展单一启发式方法具有挑战性，因为早期组件选择可能忽略具有后期潜力的组件，而独立进化则忽视组件间依赖关系。我们提出MuEvo，一种在集成级反馈下进化启发式集成的LLM驱动框架。MuEvo结合了动态组件管理（使用短预算探测和可逆生命周期在整个搜索过程中修正组件优先级）与LLM驱动的协同进化（通过多集成评估、跨组件信息共享、关系引导对进化和自适应预算分配协调组件种群）。我们在四个组合优化领域的选择超启发式和组件化蚁群优化上评估MuEvo。结果表明，MuEvo持续改进人工设计的框架，并优于最先进的LLM-AHD方法的代表性多组件扩展，证明其在控制器介导的启发式池和功能分化的算法组件上的有效性。

## Abstract
Large language model-based automated heuristic design (LLM-AHD) has shown strong potential in discovering effective heuristics for combinatorial optimization problems. However, existing methods primarily optimize a single heuristic, whereas practical optimization frameworks often rely on multiple interacting components. Directly extending single-heuristic methods is challenging because early component selection can overlook components with late potential, while independent evolution ignores inter-component dependencies. We propose MuEvo, an LLM-driven framework for evolving heuristic ensembles under ensemble-level feedback. MuEvo combines Dynamic Component Management, which uses short-budget probing and a reversible lifecycle to revise component priorities throughout the search, with LLM-Driven Co-Evolution, which coordinates component populations through Multi-Ensemble Evaluation, Cross-Component Information Sharing, Relation-Guided Pair Evolution, and Adaptive Budget Allocation. We evaluate MuEvo on selection hyper-heuristics and componentized ant colony optimization across four combinatorial optimization domains. Results show that MuEvo consistently improves human-designed frameworks and outperforms representative multi-component extensions of state-of-the-art LLM-AHD methods, demonstrating its effectiveness across both controller-mediated heuristic pools and functionally differentiated algorithmic components.

- **LLM-AHD 的兴起**：大语言模型（LLM）作为搜索算子，以极少的专家知识实现了高性能启发式自动发现（如 FunSearch、ReEvo、MCTS-AHD 等）。

# 2. 论文提出的方法论

## 2.1 核心思想

MuEvo 将“一次性组件选择 + 独立优化”转换为一个**由集成级反馈驱动的动态协同进化过程**，保留所有有效组件但赋予其可逆优先级，并通过跨组件信息共享与联合进化促进组件间的适应。

## 2.2 动态组件管理（Dynamic Component Management）

- **短预算组件探测**：在保持其他组件固定时，用短暂预算单独进化每个组件，计算探测得分：
  \[
  S_{\text{probe}}^i = f_0^i - f_*^i
  \]
  分数越大说明该组件在固定伙伴下改进潜力越大。
- **可逆生命周期**：根据探测分数排序，前 \(K_A\) 个组件设为 Active，其余设为 Inactive。Active 组件若连续多次被拒绝则进入冷却/失活；Inactive 组件在全局停滞时可按优先级重新激活。激活优先级综合评估拒绝次数、探测分数、历史替换增益、激活次数等，使得“低估组件”可重新进入搜索。

## 2.3 LLM 驱动的协同进化（LLM-Driven Co-Evolution）

- **组件独立种群**：为每个组件维护一个独立种群，采用类似 ReEvo 的反思引导交叉与变异。
- **多集成评估（Multi-Ensemble Evaluation）**：将候选组件放入三个代表性协作上下文（当前最优集成、固定初始集成、从存档中选择的 Secondary 集成）中评估：
  \[
  \Delta_i^k = f(E_k) - f(E_k[h_i \leftarrow h_i'])
  \]
  \[
  R_i = \sum_k w_k \Delta_i^k + \lambda_{\min} \min_k \Delta_i^k - \lambda_{\text{var}} \mathrm{Std}(\{\Delta_i^k\})
  \]
  只有当 \(\Delta_i^{\text{Best}} > 0\) 且 \(R_i > 0\) 时接受。上下文相关的改进向量被保留，作为后续协同进化的证据。
- **跨组件信息共享（Cross-Component Information Sharing）**：基于当前组件实现和关系记忆（每对组件的历史依赖、协作版本、上下文相关增益等）构建目标特定的“关系上下文”，注入 LLM 变异提示，使一个组件种群的证据指导其他组件的进化。
- **关系引导对进化（Relation-Guided Pair Evolution）**：每隔 \(q\) 轮，根据结构依赖和经验交互证据选出最有可能协同的组件对，将它们作为单一联合候选进行共同精化和评估，共同接受或拒绝。
- **自适应预算分配（Adaptive Budget Allocation）**：根据改进率、适应度方差、近期停滞情况、集成级奖励和分配频率计算选择分数：
  \[
  P_i = w_I I_i + w_V e^{V_i} + w_S \min(z_i/H_z, 1) + w_R e^{r_i} - w_\rho \rho_i
  \]
  选择得分最高的活跃组件进行下一轮常规进化。

## 2.4 算法流程

1. 探测所有有效组件，初始化 Active/Inactive 状态。
2. 初始化全局集成和搜索状态。
3. 在进化预算内循环：
   - 根据预算分配策略选择目标组件或组件对；
   - 构建关系上下文；
   - 用 LLM 进化生成候选实现；
   - 通过多集成评估得到结果；
   - 接受则替换全局集成并更新上下文；
   - 更新组件生命周期、关系记忆、分配统计。

- **组件化蚁群优化（ACO）**：九个组件分布在 ACO 工作流的不同阶段，体现“功能分化 + 结构化依赖”的交互结构。

- **TSP**：TSPLib 实例，划分为 TSP-SS、TSP-S、TSP-M、TSP-L，共 112 个测试实例

- **BP**：在线装箱问题（Bin Packing），采用公开基准集，考察启发式在**在线决策**场景下的适应性与鲁棒性。

四个领域在求解范式、组件交互模式与目标函数形态上具有显著差异，用于全面评估 MuEvo 的通用性。

## 3.3 基准方法与对比设置

- **人工设计的强基线**：每个领域选取代表性高性能算法（如 TSP 的 LKH、CVRP 的混合遗传算法等），用于衡量自动发现启发式的绝对性能上限。
- **传统 AHD 方法**：基于遗传编程（GP）的启发式自动发现方法，作为无 LLM 参与的对比。
- **单启发式 LLM-AHD 方法**：包括 FunSearch、ReEvo、MCTS-AHD、LLM 结合进化策略等方法。这些方法每次只优化一个启发式组件，无法直接处理多组件集成；实验中将它们扩展为“顺序独立进化各组件”的弱耦合版本，以公平比较。

## 3.4 评估指标与实现细节

- **指标**：各领域的百分比最优间隙（gap）、求解质量、收敛速度、组件发现效率（达到目标质量所需的 LLM 调用次数）等。
- **实验次数**：每个方法独立运行多次，报告均值与标准差。
- **LLM 设置**：使用 GPT-4 系列模型作为底层 LLM，温度设为 0.7；每次进化生成 8 个候选实现；关系记忆容量与生命周期参数按领域单独调优。

# 4. 实验结果与关键发现

## 4.1 整体性能对比

- 在 TSP、CVRP、BP、JSP 全部基准上，MuEvo 发现的启发式集成均显著优于**所有单启发式 LLM-AHD 基线**，平均 gap 降低约 30%–60%；在部分中小规模实例上达到或接近人工设计强基线的水平。
- 相比传统 GP 方法，MuEvo 的收敛速度与最终质量均大幅领先，说明 LLM 语义先验与协同进化机制明显优于基于语法树随机变异的传统 AHD。

## 4.2 动态组件管理的有效性

- 在实验初期，某些组件（如 ACO 中的信息素更新规则）在固定协作环境下探测分数较低，被置于 Inactive 状态；但随着其他组件进化，这些组件重新激活后产生了显著的增益。
- 与“静态 top-k 选择”基线相比，MuEvo 的**可逆生命周期**使最终集成质量提高 10%–25%，并且避免了早期错误选择导致的不可逆劣化。

## 4.3 协同进化的增益

- 多集成评估中，同一条候选组件在不同协作上下文中表现出**互补而非一致**的贡献。MuEvo 通过加权收益与方差惩罚，成功甄别出“特定环境下才有效”的组件，保留了搜索多样性。
- 跨组件信息共享使某一组件的改进经验（如“扩大候选列表的多样性”）能启发其他组件（如“调整局部搜索的扰动强度”），实验显示该机制显著减少了无效 LLM 调用。
- 关系引导对进化在 JSP 和 CVRP 上效果尤为明显：结构上相互依赖的组件对（如“路径构建规则”和“路径修复规则”）联合进化后的性能提升远大于各自独立进化。

## 4.4 消融与鲁棒性分析

- **移除动态管理**：性能下降明显，尤其是在大规模实例上，说明组件间的协同时机比静态分配更重要。
- **移除多集成评估**：候选接受率飙升但集成质量反而下降，证实单上下文评估无法准确反映组件在协作关系中的真实价值。
- **移除关系上下文**：LLM 生成的候选实现语义相关性显著降低，大量变异陷入局部重复。
- **预算敏感性**：MuEvo 在较低 LLM 调用预算下仍能稳定超越单启发式基线，证明其预算分配策略有效。

# 5. 结论与展望

- **核心结论**：MuEvo 首次将 LLM 驱动的自动启发式发现从“单组件优化”提升到“多组件协同进化”层面，通过集成级反馈、动态生命周期和跨组件信息共享，系统性地解决了组件选择不可逆与独立进化缺乏协同的两大挑战。
- **方法论意义**：论文提出的“组件-集成”双层模型、关系记忆机制与多上下文评估范式，可推广至其他多组件协同优化任务（如自动机器学习流程设计、神经网络架构搜索的组合模块调优等）。
- **未来方向**：进一步引入多模态反馈（如运行时特征、问题结构嵌入），探索组件间复杂交互的可解释性，并将 MuEvo 扩展到持续学习与跨问题迁移场景。
