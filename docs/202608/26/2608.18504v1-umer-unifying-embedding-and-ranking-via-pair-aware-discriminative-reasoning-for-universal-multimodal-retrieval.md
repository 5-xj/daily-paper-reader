## 摘要
通用多模态检索旨在支持多样化的指令感知检索任务，既需要高效的语料库规模匹配，也需要细粒度的语义推理。近期基于MLLM的嵌入方法通常从隐藏状态中导出表示，而思维链（CoT）推理正成为一种有前景的嵌入增强策略，通过将中间语义证据编码到表示空间中。然而，现有的CoT方法通常对查询和候选进行孤立的逐项推理，无法提供明确的证据来区分正例与语义上易混淆的难负例。此外，对比嵌入捕捉全局相似性，但在需要答案验证、类别判断或细粒度推理的元任务上表现不佳。本文提出了UMER，一个用于通用多模态检索的统一多模态嵌入与排序框架。UMER用成对感知判别推理取代逐项反思，通过比较查询-候选对来识别与指令相关的匹配和差异证据。UMER在单一MLLM中联合学习用于高效全局匹配的对比嵌入和用于显式成对相关性判断的判别排序。互补的相互蒸馏策略进一步在嵌入函数与排序函数之间转移可靠的成对偏好。在MMEB-V2基准上，UMER在可比较的实验设置下取得了最先进的性能，同时支持预算可调的推理。

## Abstract
Universal multimodal retrieval aims to support diverse instruction-aware retrieval tasks, demanding both efficient corpus-scale matching and fine-grained semantic reasoning. Recent MLLM-based embedding methods typically derive representations from hidden states, while Chain-of-Thought (CoT) reasoning is emerging as a promising strategy for embedding enhancement by encoding intermediate semantic evidence into the representation space. However, existing CoT methods typically use item-wise reasoning over queries and candidates in isolation, providing no explicit evidence to distinguish a positive from a semantically confusable hard negative. Moreover, contrastive embeddings capture global similarity but struggle with meta-tasks requiring answer verification, category judgment or fine-grained reasoning. In this paper, we propose UMER, a Unified Multimodal Embedding and Ranking framework for universal multimodal retrieval. UMER replaces item-wise reflection with Pair-Aware Discriminative Reasoning, which compares query--candidate pairs to identify instruction-relevant matching and discrepancy evidence. UMER jointly learns contrastive embeddings for efficient global matching and discriminative ranking for explicit pairwise relevance judgment within a single MLLM. A complementary mutual distillation strategy further transfers reliable pairwise preferences between the embedding and ranking functions. On the MMEB-V2 benchmark, UMER achieves state-of-the-art performance under comparable experimental settings while supporting budget-adjustable inference.

## 2. 方法论：核心思想、关键技术细节与算法流程

### 2.1 总体框架
- UMER 在同一个 MLLM 中学习两个互补函数：
  1. **嵌入函数（Embedding）**：独立计算查询和候选的表示，用于语料库规模向量索引和近似最近邻检索；
  2. **排序函数（Ranking）**：通过成对感知判别推理显式判断查询-候选相关性，用于复杂任务和难样本的精细重排。
- 两个函数共享 MLLM 主干，但通过不同的注意力掩码和任务专用 token 保持独立信息流。

### 2.2 嵌入编码阶段
- 对每个输入（查询或候选）追加 **M 个可学习嵌入 token**（本文 M=4），并在分支级注意力掩码下仅让这些 token 关注自身输入。
- 对嵌入 token 的隐藏状态进行均值池化并做 ℓ2 归一化，得到独立可索引的嵌入向量：

  $$e_x = \text{Norm}\left(\frac{1}{M}\sum_{k=1}^{M} h_x^k\right), \quad x \in \{q, c\}$$

- 使用**批内对比损失**（含挖掘的难负例）优化嵌入空间：

  $$\mathcal{L}_{\text{emb}} = -\frac{1}{B}\sum_{i=1}^{B} \log \frac{\exp(s_e(q_i, c_i^+))}{\sum_{c \in \{c_i^+\} \cup N_i} \exp(s_e(q_i, c))}$$

  其中 $s_e(q,c) = e_q^\top e_c / \tau_e$ 为温度缩放的余弦相似度，$N_i$ 为批内候选项与挖掘的难负例。

### 2.3 成对感知推理与排序阶段
- 对每个正例对或难负例对 $(q, c^a)$，先通过分支注意力编码输入，然后拼接固定提示 P，并以**全成对注意力**自回归生成成对感知推理轨迹 $R^a$。
- 与逐项自反思不同，推理输入同时包含查询和候选，模型需要显式比较匹配证据（正例）或差异证据（难负例）。
- 使用**标准 token 级交叉熵损失**监督推理轨迹生成：

  $$\mathcal{L}_{\text{cot}} = \sum_{a \in \{+,-\}} \text{CE}(g^a; X^a)$$

- 在推理轨迹之后添加可学习的 `[RANK]` token，其对全序列进行注意力并输出相关性 logit：$z_{q,c^a} = w^\top h_{[\text{RANK}]} + b$。
- 两个排序损失：
  - **二元交叉熵损失**：对正例对预测 1、难负例对预测 0；
  - **成对 logistic 排序损失**：鼓励正例 logit 高于难负例 logit。

### 2.4 成对感知判别 CoT 数据构建
采用三步生成与过滤流程：
1. **难负例挖掘**：用冻结的现成多模态嵌入器对每个查询检索 Top3 语义最接近但非相关的候选作为难负例。
2. **结构化 CoT 生成**：用 Qwen3.5-9B 对每个正例对或难负例对生成包含 `Query Intent` 与 `Target Observations` 两个字段的结构化成对推理，省略显式 Yes/No 答案，迫使相关性从证据中推断。
3. **证据充分性过滤**：用轻量文本验证器（Qwen3.5-0.8B）仅依据生成的 CoT 判断正/负标签，只有通过验证的三元组才被保留用于训练。

### 2.5 互补互蒸馏（Complementary Mutual Distillation, CMD）
- 嵌入和排序各自擅长不同的任务族：检索、定位/时刻检索（内容匹配）由嵌入主导；分类、问答（推理密集型）由排序主导。
- CMD 通过**选择性门控**只传递可靠偏好：只有参考模型在对应任务族上正确排序时才激活单向蒸馏信号，防止不可靠偏好传播。
- 损失形式为双向 KL 散度：

  $$\mathcal{L}_{\text{cmd}} = g_{e\to r}\,\text{KL}(\text{sg}[\bar{\pi}_e]\|\pi_r) + g_{r\to e}\,\text{KL}(\text{sg}[\bar{\pi}_r]\|\pi_e)$$

  其中 $\text{sg}[\cdot]$ 停止梯度，$g$ 为任务族相关门控。

### 2.6 三阶段渐进训练与灵活推理
- **三阶段训练**：
  1. 只用嵌入对比损失在完整 MMEB 训练集上学习稳定的可索引嵌入空间；
  2. 在验证三元组上加入 CoT 生成、二元排序和成对排序损失；
  3. 冻结第二阶段模型作为参考，加入 CMD 损失进行跨能力偏好迁移。
- **灵活推理**：
  - `UMER-E`：仅嵌入检索，单次前向得到嵌入并向量索引，无自回归推理；
  - `UMER-R`：嵌入检索 Top-K 后，对每个候选用成对推理 + 排序 logit 重排；
  - `UMER-H`：混合模式，将嵌入分数与排序分数在 Top-K 内分别 z-score 归一化后加权融合：

    $$s_{\text{hyb}}(q,c) = \hat{s}_e(q,c) + \alpha \hat{z}_{q,c}$$

## 6. 主要结论与发现

- **成对感知判别推理优于逐项自反思 CoT**：在嵌入层，UMER-E 相比基于逐项 CoT 的 UME-R1，将宏平均正例-硬负例余弦间隔从 5.24 提升到 6.80（×10⁻²），且在更严格间隔阈值下优势更大（+5.0/6.8 个百分点）。
- **嵌入与排序具有系统能力专门化**：检索与定位类任务嵌入更强，分类与问答类任务排序更强，这种互补性在同一模型内部真实存在且可被利用。
- **CMD 能有效转移互补能力**：选择性门控双向蒸馏使嵌入在推理密集任务、排序在内容匹配任务上都获得一致增益，同时保留各分支专长。
- **统一框架达到 SOTA**：2B 模型 UMER-H 在 MMEB-V2 上总体 65.5（超过 RIME 64.1 约 1.4 分），图像/视频/视觉文档分别为 70.4/45.0/73.6；7B 模型总体 70.6。
- **预算可调推理有效**：从纯嵌入（UMER-E）到混合重排（UMER-H）可按预算动态增减推理开销，默认 K=5 在 24% 的 K=20 延迟下获得 80% 的最大增益，具有良好精度-效率平衡。

## 7. 优点

- **问题定位清晰**：明确指出逐项 CoT 的“无成对证据”缺陷和“不同元任务需要不同能力”的异质性，两个动机均有数据支撑（Fig. 1、Fig. 4a）。
- **框架设计统一且实践性强**：将嵌入、CoT 生成、成对排序统一在单个 MLLM 中，训练时共享主干但通过注意力掩码保持独立，推理时支持多种模式，兼顾大规模检索与细粒度重排。
- **数据构建严谨**：难负例挖掘 + 结构化 CoT 生成 + 轻量验证过滤的三步流程，确保 CoT 包含足够的判别证据而非“流畅但无效”的文本；用文本验证器做审计是一种低成本且可扩展的质量控制手段。
- **蒸馏设计有选择性**：不是强制嵌入与排序一致，而是按任务族门控+参考模型正确性门控，避免错误偏好传播，这种“保留互补、收敛盲区”的思路较新颖。
- **实验证据充分**：从整体指标、逐任务详情、消融、间隔分析、能力迁移、效率权衡、决策互补性到定性案例，形成完整证据链；决策重叠分析科学地量化了融合的收益来源。
- **效率评测明确**：报告了查询延迟、索引时间、推理 token 数等实际部署指标，并展示了不同 K 下的预算-精度曲线，为实际应用选取配置提供了依据。

## 8. 不足与局限

- **训练成本未充分披露**：没有报告 GPU 数量、训练时长、总 FLOPs 或能耗，难以与现有方法进行完整成本对比；只在推理端给出单卡 A100 指标。
- **未做统计显著性检验**：缺少多次运行的平均值和方差，未报告随机种子设置，结论可能受单次运行波动影响。
- **COT 生成依赖外部模型**：训练数据由 Qwen3.5-9B 生成、Qwen3.5-0.8B 验证，质量受生成模型能力限制，且对视频/文档的 CoT 生成采样较少（每种仅 1 条），可能造成难样本覆盖不均。
- **推理成本在 ranking 模式下仍较高**：UMER-H 在 K=20 时单个查询约需 81.7 秒，且生成有 256 token 上限；海量在线查询场景下成本偏高，文中未给出批处理吞吐优化。
- **混合融合权重 α 为超参数**：默认 α=2.0 且只在 Top-K 内做 z-score 归一化，对该归一化方式的合理性（分布假设）论证有限，跨不同类型查询的自适应融合有待探索。
- **任务局限性**：主要性能验证基于 MMEB-V2 单一基准，缺少在更大规模、更多语言或更多难负例分布上的外部验证；文中亦未讨论多语言、跨语种检索场景。
- **失败案例分析显示 ranking 对空间关系判断可能退化**：Case 4 显示成对 CoT 过度关注显著前景而丢失“背后/右侧”的相对位置约束，说明判别推理并不总是优于全局嵌入，模型仍存在特定语义短板。
