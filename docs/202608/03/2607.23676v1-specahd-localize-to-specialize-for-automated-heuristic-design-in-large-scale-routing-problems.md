## 摘要
基于大语言模型的自动化启发式设计（AHD）通常在完整实例或固定求解器组件内对可执行程序进行评分。在大规模路由问题中，局部重构缩小了每个优化任务的规模，但同一当前解中的修复区域可能呈现显著不同的结构。因此，单一构造规则必须在这些区域之间进行折中。本文提出SpecAHD，一种用于实例内特化的耦合双层框架。上层搜索学习在何处暴露有界修复区域，而下层搜索则为诱导出的修复任务演化出一组互补的可执行启发式算法。上层程序决定下层所见修复任务，而检查后的修复结果决定上层程序如何评估。下层目标倾向于在平均情况下表现良好或能解决当前候选池处理不佳任务的启发式算法。对于由固定上层程序和固定下层候选池诱导的修复任务，该目标是单调子模的，从而允许以(1-1/e)近似保证进行贪婪候选选择。在四个路由问题和多个大语言模型骨干上，SpecAHD相比最强的竞争AHD基线将留出目标成本最多降低57.7%，并在大多数公共实例上优于逐实例基线包络。

## Abstract
LLM-based automated heuristic design (AHD) typically scores executable programs on complete instances or within fixed solver components. In large-scale routing problems, localized reconstruction reduces the size of each optimization task, but repair regions within the same incumbent can exhibit substantially different structures. One construction rule must therefore compromise across them. In this paper, we propose SpecAHD, a coupled bilevel framework for within-instance specialization. An upper-level search learns where to expose bounded repair regions, while a lower-level search evolves a complementary repertoire of executable heuristics for the induced repair tasks. The upper-level program determines the repair tasks seen by the lower level, while checked repair outcomes determine how upper-level programs are evaluated. The lower-level objective favors heuristics that perform well on average or solve tasks that the current repertoire handles poorly. For the repair tasks induced by a fixed upper-level program and a fixed lower-level candidate pool, this objective is monotone submodular, allowing greedy repertoire selection with a (1-1/e) approximation guarantee. Across four routing problems and multiple LLM backbones, SpecAHD reduces held-out objective cost by up to 57.7% against the strongest competing AHD baseline and outperforms the per-instance baseline envelope on most public instances.

## 一、核心问题与整体含义

- **研究背景**：在大规模路由问题（如 CVRP、TSP、VRPTW、SDVRP）中，常见的优化策略是“局部重构”（Large Neighborhood Search, LNS），即从当前可行解中暴露一部分区域并重新构造。传统 LLM 驱动的自动化启发式设计（AHD）通常在完整实例上评价一个全局启发式程序，或者只搜索固定的求解器组件。
- **核心问题**：同一当前解（incumbent）内不同修复区域的结构差异很大，用单一的构造规则去适配所有修复区域必然产生折中；而“修哪里”和“怎么修”两个决策又是相互依赖的，独立搜索难以区分好坏。
- **整体含义**：本文提出 **SpecAHD**，将“特化”从跨实例层面推进到**实例内部**：通过耦合双层搜索，同时学习“选择修复区域”与“为不同区域选择互补的修复启发式”，从而提升大规模路由问题的求解质量和泛化能力。

## 二、方法论

### 1. 核心思想

- 采用**耦合双层框架**：
  - **上层搜索（Upper-level）**：学习生成有界修复区域（region exposure），决定下层看到哪些修复任务。
  - **下层搜索（Lower-level）**：为上层诱导出的修复任务演化一组互补的可执行启发式程序（repertoire）。
- 上下层通过**检查后的修复结果**互相联系：上层程序决定下层任务，下层修复的实测效果再用于评估上层程序。
- 引入**修复响应归档（Repair Response Archive）**，存储结构描述符、启发式程序与检查后的修复得分，在推理时按局部结构路由到合适的启发式。

### 2. 关键技术细节

- **问题接口**：每个路由问题定义验证器 \(V_p\)、描述符 \(\Phi_p\)、重构算子 \(R_p\)、合并算子 \(M_p\) 和精确检查器 \(F_p\)。上层程序 \(g\) 输出原始区域提议，验证器过滤掉空、重复、过大和局部无效的区域，得到有界修复序列 \(z=(z_1,\dots,z_L)\)。
- **检查式合并**：对每个区域 \(j\)，执行启发式 \(h\) 得到局部重构，合并后用精确检查器 \(F_p\) 检查完整解；若不可行则回滚到原可行解。这保证**顺序修复后的完整解始终可行**（命题 1）。
- **响应得分**：对单区域任务 \(r\)，启发式 \(h\) 的检查后响应分数为：
  \[
  s_{h,r} = \frac{[C_x(y) - C_x(\Gamma_p(r,h))]^+}{\max\{\epsilon, C_x(y)\}}
  \]
- **候选池目标函数**：对于固定上层程序 \(g\) 和候选池 \(P_g\)，选择规模不超过 \(q\) 的子集 \(H\) 最大化：
  \[
  J_g(H) = \beta \sum_{h\in H} \bar{s}_g(h) + \frac{1-\beta}{n_g}\sum_{r\in R_g}\max_{h\in H} s_{h,r}
  \]
  其中第一项奖励平均质量，第二项奖励任务覆盖（互补性），\(\beta\) 平衡二者。
- **理论保证**：对固定的 \(g\)、任务集和候选池，\(J_g\) 是单调子模函数，贪心选择可获得 \((1-1/e)\) 近似保证（命题 2）；当 \(\beta=0\) 且得分为二值时问题等价于最大覆盖，是 NP-hard。
- **上层目标**：用冻结的修复系统评估上层候选，目标为训练实例上的平均归一化改进减去惩罚项（惩罚空区域、验证拒绝率和合并回滚率）。
- **交替搜索流程**：一轮为 \(g_t \to R_{g_t} \to S_t \to (H_{t+1}, A_{t+1}) \to g_{t+1}\)，在有限预算下交替更新上下层。
- **条件路由**：路由器用结构描述符的 \(k\) 近邻加权相似度估计每个启发式在新区域上的响应，选择得分最高的程序；若相似邻居中无观测则回退到归档平均分。

## 六、主要结论与发现

- 在四个路由问题和多个 LLM 骨干上，SpecAHD 相比最强 AHD 基线将留出目标成本**最高降低 57.7%**。

## 七、优点

1. **问题定位准确**：将 AHD 从“选一个全局最优程序”转变为“为局部结构选择互补专家”，契合 LNS 的真实决策耦合。
2. **理论上有据可依**：下层目标函数被证明为单调子模，给出贪心选择的 \((1-1/e)\) 近似保证。
3. **可行性有保障**：精确检查器 + 回滚机制保证任何失败或不可行合并都不会破坏完整解可行性。
4. **响应归档机制**：用检查后的任务级响应而非单一聚合分数来选程序和路由，信息利用更充分。
5. **实验较全面**：覆盖多个问题、规模、骨干、基线和公共基准，并公开了逐实例结果与审计轨迹，可复现性较强。
6. **训练/推理分离**：推理时冻结全部组件，不需要再调用 LLM，实际服务成本可控。

## 八、不足与局限

1. **理论保证有限**：\((1-1/e)\) 只针对固定上层程序、固定任务集和候选池的贪心选择，不保证交替双层搜索的收敛性或全局最优性。
2. **依赖手工描述符**：结构描述符需要针对每个问题手工设计，路由质量会受描述符表达能力影响。
3. **归档路由脆弱性**：当归档邻域稀疏或测试结构发生分布偏移时，路由可能退化。
4. **未建模修复间交互**：顺序修复中后续区域看到的解状态会受之前修复影响，但目标函数和路由没有显式处理这种交互。

6. **资源信息不完整**：未报告 GPU 型号、训练总时长和能耗，复现成本难以准确估计。
7. **骨干依赖明显**：GLM 和 DeepSeek 两个变体在不同问题/规模上各有强弱，说明方法对 LLM 骨干有一定敏感性。
