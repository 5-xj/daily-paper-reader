## 摘要
学习优化（L2O）方法通过训练模型来预测解、热启动、分支决策或其他形式的求解器指导，从而加速重复优化。这些流程中一个关键但常被忽视的组成部分是特征函数，它将问题实例映射为机器学习模型的输入。现有的L2O方法通常依赖手工设计的特征，使得表示设计成为手动过程，并且在跨领域时基本固定。我们提出了FunL2O，这是第一个通过LLM驱动的程序进化来自动化L2O特征设计的统一框架。在FunSearch风格的循环中，LLM提出可执行的特征函数，而固定的评估过程则重新训练原始L2O模型并测量下游优化性能。我们在涉及解预测和热启动的线性与二次规划任务，以及使用GNN引导的后门分支和预测-搜索的混合整数优化任务上评估了FunL2O。在连续和离散优化任务以及四种LLM上，进化出的特征始终优于手工设计的表示。这些结果确立了LLM驱动的特征进化作为自动化L2O中表示设计的一种通用且有效的方法。

## Abstract
Learning-to-optimize (L2O) methods accelerate repeated optimization by training models to predict solutions, warm starts, branching decisions, or other forms of solver guidance. A critical yet largely overlooked component of these pipelines is the feature function that maps problem instances to inputs for machine learning models. Existing L2O methods typically rely on hand-crafted features, making representation design manual and largely fixed across domains. We introduce FunL2O, the first unified framework for automating feature design through LLM-driven program evolution for L2O. In a FunSearch-style loop, an LLM proposes executable feature functions, while a fixed evaluation process retrains the original L2O model and measures downstream optimization performance. We evaluate FunL2O on linear and quadratic programming tasks involving solution prediction and warm-starting, as well as on mixed-integer optimization tasks using GNN-guided backdoor branching and Predict-and-Search. Across continuous and discrete optimization tasks and four LLMs, the evolved features consistently outperform hand-crafted representations. These results establish LLM-driven feature evolution as a general and effective approach to automating representation design in L2O.

- **研究背景**：学习优化（L2O）方法利用已求解实例训练神经网络，以加速重复优化任务——例如预测解、热启动迭代算法、选择单纯形基、指导混合整数搜索等。然而，所有L2O流程的起点都依赖于一个关键却常被忽视的组件：**特征函数**，它将优化实例映射为机器学习模型的输入张量。
- **核心问题**：现有L2O方法的特征函数基本依赖**手工设计**，且在不同问题域间固定不变。这种表示设计方式既耗时，又可能遗漏对模型性能至关重要的结构关系——因为特征函数决定了模型能直接利用哪些信息，而模型无法轻易推断未显式提供的关系。
- **核心挑战**：自动化特征设计并非简单的特征选择问题。L2O特征函数需要满足以下苛刻要求：
  - 必须是可执行程序，且要维持模型特定的张量接口；
  - 必须满足语义和维度不变性；
  - 只能依赖部署时可获得的信息；
  - 其质量只能在重训模型并测量下游优化性能后才能评估。
- **论文贡献**：提出 **FunL2O**——首个通过LLM驱动的程序进化来自动设计L2O特征函数的统一框架。核心思想是：在FunSearch风格的循环中，由LLM提出可执行的特征函数，通过固定的评估流程（重训原始L2O模型并测量下游优化性能）来筛选和进化。论文在LP、QP、混合整数优化等多个任务上验证了该方法的一致有效性。

## 2. 方法论

### 2.1 核心思想

- FunL2O将特征函数设计**重构为程序搜索问题**：在原始L2O流水线内部搜索可替代手工特征函数的可执行程序。
- 搜索过程中**只改变输入表示**，其余部分（模型架构、训练过程、超参数、数据、学习角色、下游求解器）全部保持不变，从而隔离输入表示对性能的影响。
- 框架定义为流水线：$x \xrightarrow{\phi} X \xrightarrow{M} a \xrightarrow{S} by$，其中 $\phi$ 为特征函数，$M$ 为学习模型，$S$ 为下游求解器。给定候选 $\phi$，模型经重新训练后得到 $a_\phi(x) = M^{(d_\phi)}_{\theta^*_\phi}(z_\phi(x))$，最终输出 $by_\phi(x) = S_P(x, a_\phi(x))$。
- 特征设计问题被形式化为：$\phi^* \in \arg\min_{\phi \in \Phi_P} \rho_P(\phi)$，其中排名键 $\rho_P(\phi) = (b_P(\phi), v_P(\phi), q_P(\phi))$ 按字典序排列，依次衡量可行性条件是否违反、不可行程度、目标质量或求解器工作量。

### 2.2 关键技术细节

- **语义特征契约**：定义 $C_P = (U_P, Z_P, I_P, V_P)$，其中：
  - $U_P$：部署时可用的实例字段或求解器状态信息；
  - $Z_P$：输出类型、方向和最大特征宽度；
  - $I_P$：必须保留的不变量（如确定性、有限输出、必需的手工特征通道）；
  - $V_P$：可执行的验证器，先静态检查候选源码安全性，再在小探针实例上动态验证函数签名、输出结构、维度、数值有限性和必需种子通道。
- **标准化提示构建**：通过统一的提示模板组织搜索信息，包括共享指令、语义契约、共享关系词汇表（如原始问题量、尺度、残差、曲率、边界、锥、图统计等）、精英函数上下文及反馈信息。LLM被要求识别当前表示未暴露的有用关系，并实现为一个特征函数。
- **L2O在环搜索循环**：
  1. 手工特征函数 $\phi_0$ 作为基线和首个有效示例初始化搜索记忆；
  2. 每一代，LLM生成6个候选特征函数；
  3. 候选通过验证器后，替换 $\phi_0$ 在原始流水线副本中重训模型；
  4. 用验证集上的下游性能（按流水线特定的排名键）评估候选；
  5. 排名最高的两个精英程序进入下一代提示上下文；
  6. 搜索结束后，选出的特征函数就是普通预处理代码，部署时无需LLM参与。

## 6. 主要结论与发现

- **一致改进**：在跨LP、QP、约束非线性、混合整数优化领域，FunL2O进化出的特征函数几乎在所有任务上优于手工特征，且改进幅度可观。例如：
  - IPM-MPNN上目标间隙降低16.4%–49.4%；
  - FSNet的非凸SOCP任务间隙从933.85%降至141.28%，可行性从0.25提高到1.00；
  - PDHG-Net迭代节省从42.44%提升至51.05%；
  - Learning to Pivot枢轴数几何均值从1162.86降至857.78（−26.2%）；
  - Predict-and-Search在MIS上最终原始间隙从0.699%降至0.095%；
  - 学习后门分支在MIS上平均墙钟时间从102.6秒降至46.0秒，获胜率从21%提升至49%。
- **改进机制是结构性的，而非简单宽度扩展**：匹配宽度的随机特征控制证明，性能增益大部分来自优化相关的语义结构，而非单纯增加输入维度。
- **进化反馈有效**：等预算独立采样对比显示，精英记忆和测量反馈带来额外7.81个百分点的迭代节省提升。
- **跨LLM的鲁棒性**：Claude、GPT-5.5和Gemini在共享的20个单元格中分别改进15、17和17个，而DeepSeek-Math-V2改进6个——说明方法不绑定于特定LLM，但更强提议模型产生成功特征函数更可靠。
- **可解释性**：进化出的程序可直接检视，暴露了原始表示遗漏的优化关系（如集合覆盖中的成本/覆盖率归一化、PageRank中的行/列质量不对称、非线性问题的多尺度变换等）。

## 7. 优点

- **问题定位精准**：精准识别出L2O领域中被长期忽视但极其重要的组件——特征函数，将其从手工固定转变为可搜索的自动化对象，具有较高价值。
- **方法设计优雅**：将LLM程序进化与L2O流水线有机结合，用语义契约处理异构模型接口，用下游原生指标作为评估信号，用“不变式保持”确保公平对比。
- **隔离变量、归因清晰**：只改特征函数，保持模型、训练、数据、求解器全部不变——这使得性能变化可以明确归因于表示设计，方法逻辑严谨。
- **通用性广**：同时覆盖直接解预测、约束解预测、热启动、基选择、枢轴选择、MILP搜索等多种学习角色，且统一框架无需定制化修改即可部署。
- **部署友好**：选出的特征函数是普通可执行预处理代码，推理时无需LLM参与；在重复优化场景中，离线搜索成本可在多实例上摊销。
- **实验验证全面**：3种随机种子配对重复、验证/测试分离、多种受控对照（等预算采样、匹配宽度、多模型、种子保留），有效排除了多种替代解释。
- **可解释性良好**：进化出的程序本身可检视、可部署，作为可解释的表示假设，面向后续优化的透明性和可审计性。

## 8. 不足与局限

- **计算成本高**：每次搜索约需25.3小时（单worker）+192美元LLM成本；若要覆盖多任务、多LLM组合，总成本线性增长，可能限制该方法在资源和预算有限场景下的可及性。
- **GPU信息缺失**：附录未明确说明GPU型号、数量和集群配置，影响可复现性和成本估算的精确性。
- **搜索效率有限**：论文采用较朴素的进化循环（只有精英保留，无交叉、变异等算子），48个候选在8代内完成搜索；更高级的搜索机制（如自适应的变异/交叉、种群多样性管理）有望进一步提升性能，论文也承认这一点。
- **强LLM依赖**：不同LLM的表现差异显著（DeepSeek-Math-V2仅改进6/20个单元格），说明方法效果在一定程度上依赖提议模型的代码生成质量；在性能较弱的开源模型上收益有限。
- **过拟合风险**：虽然使用验证/测试分离缓解了过拟合风险，但搜索过程本身在固定验证集上的反复重训和评估仍可能对验证分布产生隐式适配；论文对跨分布推广性（如从集合覆盖迁移到其他LP分布）讨论不足。
- **应用范围局限**：实验集中在中小规模问题（FSNet的1000变量、集合覆盖实例、40实例的MILP基准），对于超大规模实际优化问题（如数万变量的LP/MILP）是否仍然有效缺乏验证。
- **零改进案例虽透明但未深析**：部分单元格（如FSNet的非凸QP、DC3的某些设置）没有改进或改进极微小，论文未对这些情况展开分析（如是否因为原始表示已足够充分、还是搜索陷入局部最优），削弱了对“何时适用、何时不适用”的理解。
- **LLM幻觉风险**：虽然动态验证器拦截了不合法程序，但逻辑上合理但数学上有害的特征（能过验证、不违反契约但损害性能）仍可能被加入候选，浪费训练预算；论文未讨论这类失败模式的频率和影响。
