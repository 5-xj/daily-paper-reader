## 摘要
软件行为通常在输入区域之间的边界处突然变化，这些转换已知容易出错。边界值探索（BVE）通过搜索相似输入对来自动化边界发现，这些输入对虽相似却触发不同的程序行为。现有的自动化BVE技术依赖于为每种输入类型甚至每个被测函数手工设计的变异算子，这限制了它们在数值输入上的使用。我们提出ABEX，一种基于智能体LLM的框架，用自适应策略生成取代算子工程：专门的LLM智能体在执行反馈和质量多样性（QD）存档的引导下，提出、选择并执行边界探索策略。由于策略以自然语言表达，它们可以编码类型级和函数特定知识，有效的策略甚至可以存储和复用。我们在黑盒设置下对20个具有数值、字符串、数组和混合输入的函数评估了ABEX。在数值函数上，ABEX在11个函数中的10个上优于最先进的QD方法，平均QD分数高出11.7倍。在非数值函数上（这是首次在自动化黑盒BVE中处理），ABEX为所有对象发现了领域对齐的边界行为。变异测试表明，发现的边界具有故障揭示能力：在同等大小的测试套件下，ABEX的平均变异得分为86.2%，而QD基线为61.9%，并且杀死的难检测顽固变异体数量是后者的九倍。消融研究确定自适应策略生成是这些收益的主要驱动因素。

## Abstract
Software behavior often changes abruptly at boundaries between input regions, and these transitions are known to be fault-prone. Boundary Value Exploration (BVE) automates boundary discovery by searching for pairs of similar inputs that nevertheless trigger different program behaviors. Existing automated BVE techniques rely on mutation operators hand-engineered for each input type, or even for each function under test, which has confined their use to numeric inputs. We present ABEX, an agentic LLM-based framework that replaces operator engineering with adaptive strategy generation: specialized LLM agents propose, select, and execute boundary-exploration strategies, guided by execution feedback and a quality-diversity (QD) archive. Because strategies are expressed in natural language, they can encode both type-level and function-specific knowledge, and effective strategies can even be stored and reused. We evaluate ABEX in a black-box setting on 20 functions with numeric, string, array, and mixed inputs. On numeric functions, ABEX outperforms a state-of-the-art QD method on 10 of 11 functions, with average QD-scores 11.7x higher. On non-numeric functions, addressed here for the first time in automated black-box BVE, ABEX discovers domain-aligned boundary behaviors for all subjects. Mutation testing shows the discovered boundaries are fault-revealing: with equally sized test suites, ABEX reaches an average mutation score of 86.2% versus 61.9% for the QD baseline, and kills nine times as many hard-to-detect stubborn mutants. An ablation study identifies adaptive strategy generation as the primary driver of these gains.

## 1. 核心问题与研究动机

**背景与问题**：
- 软件系统的行为常在输入区域边界处发生突变，这些边界区域是缺陷的高发地带。边界值探索（BVE）将边界发现转化为搜索问题：寻找“输入相近但行为不同”的输入对，从而暴露行为边界。
- 现有自动化 BVE 方法（如 AutoBVA、SETBVE）存在根本性局限：**依赖为每种输入类型甚至每个被测函数手工设计的变异算子**。数值输入的变异算子易于设计（如对阈值加减 1），但对于字符串、数组、结构化输入等复杂类型，手工设计算子极为困难且难以规模化。
- 以电子邮件验证函数为例，`alice@example.com` 与 `alice@@example.com` 之间仅有微小语法差异，却涉及完全不同的边界条件，需要领域特定知识才能有效探索。
- 因此，自动化 BVE 长期被困于数值域，而真实软件大多运行在更丰富的输入结构上。

**研究目标**：消除对手工算子工程的依赖，将 BVE 扩展到数值输入之外的广阔领域。

## 2. 方法论：ABEX 框架

**核心思想**：用 **LLM 智能体自适应生成、选择、执行"边界探索策略"**，以执行反馈和 QD 档案引导搜索。策略以自然语言表达，可编码类型级与函数特定知识，并且**可存储、可复用**。

### 2.1 边界探索策略（Strategy）的形式化定义

策略是四元组 $s = (m, t, P)$：
- $m \in \{\text{generation}, \text{mutation}\}$：策略模式。生成模式从零开始产生新输入对；变异模式从档案中采样已有输入对并做微小修改。
- $t \in \{\text{generic}, \text{context-aware}\}$：策略类型。通用策略只知道输入参数的数量与数据类型；上下文感知策略还掌握函数签名和 docstring，可利用领域知识。
- $P = \langle p_1, p_2, \ldots, p_k \rangle$：有序自然语言步骤序列，指导如何生成候选输入对。

### 2.2 三层智能体架构

受管理学中战略—战术—操作三层决策模型启发，ABEX 采用三层架构：

**① 战略层：协调器（Coordinator）**
- 决定探索方向：重复当前策略 / 从策略池中选择其他策略 / 请求生成新策略。
- 接收迭代进度、最近档案更新、停滞指标、策略池使用统计（总成功率 + 时间衰减成功率）等上下文信息。
- 生成新策略时需指定**策略模式、类型、搜索缺口（search gap）**。

**② 战术层：构思器（Ideator）+ 策略生成器（Strategy Generator）**
- Ideator：将协调器的搜索缺口转化为 1-2 句的“战术想法”；比较 2-3 个候选方向，依据**搜索缺口相关性、功能新颖性（而非仅文本相似性）、预期产出**进行筛选。例如，“整数溢出边界”和“接近 MAX_INT 的值”文本不同但功能冗余，需要被识别。
- Strategy Generator：将选中的想法细化为可执行的分步探索程序，并在步骤中引入多样性，确保重复执行能产生不同候选。

**③ 操作层：探索器（Explorer）**
- 执行文本策略，调用 LLM 每轮生成 N=10 个输入对。
- 通过 **MAP-Elites 风格的 QD 档案**评估候选：四维行为描述子（异常数量、输出长度差、序列化输入总长度、输入长度方差），无需分箱，每个整数向量构成独立档案格。
- 质量度量采用**程序导数（PD）**：$PD(i_1,i_2) = d_o(o_1,o_2) / d_i(i_1,i_2)$，输出距离用 Jaccard 距离，输入距离在数值域用欧氏距离、混合域用逐元素距离平均。
- 档案更新遵循 MAP-Elites 策略：空格直接插入，占据格仅当新候选 PD 更高时替换。
- 停止条件：连续 10 次迭代或连续 3 次无档案更新后，返回协调器。

### 2.3 关键设计细节

- 异构模型配置：高频调用的 Explorer 和 Strategy Generator 用 GPT-5-mini（低成本），战略性决策的 Coordinator 和 Ideator 用 GPT-5.1（强推理）。
- 采样温度按角色区分：协调器和策略生成器用 0.5，构思器和探索器用 0.8 以促进多样性。
- 探索器提示中注入档案中最近添加和随机采样的输入对，避免生成重复候选。
- 基于 DSPy 框架实现声明式 LLM 流水线。

## 6. 主要结论与发现

1. **数值边界发现（RQ1）**：ABEX 在 11 个数值 FUT 中的 10 个上取得最高 QD-score，平均值 18.7，是单提示基线（6.7）的 **2.8 倍**、SETBVE（1.6）的 **11.7 倍**。约 99% 的 SETBVE 边界候选 PD < 0.001，而 ABEX 平均 PD 高约 150 倍。唯一例外是 bytecount（SETBVE 更高）。复杂函数上单提示基线完全失效（0 候选），而 ABEX 仍能发现边界。

2. **非数值边界发现（RQ2）**：**首次在自动化黑盒 BVE 中探索非数值输入**。字符串、数组、混合输入的全部测试对象均发现了领域对齐的边界行为（如密码强度等级转换、词法 token 类型变化、数组排序前后差异、二分查找边界索引变化等）。边界类型在多数情况下 8-10/10 次运行中稳定复现。

3. **策略分工（RQ3）**：**生成类策略驱动覆盖广度，变异类策略驱动质量精化**。例如在数值域，通用生成的 NC/10 最高（2.49），变异策略的 BS/10 最高（0.42），形成一致的探索—利用分工模式。

4. **故障检测（RQ4）**：同等大小测试套件下，ABEX 平均变异得分 **86.2% vs SETBVE 的 61.9%**；即使 SETBVE 获得两倍候选数（63.7%）仍无法追平。顽固突变体方面，ABEX 杀灭 95.5/190（50.3%），SETBVE 仅杀灭 10.6（5.6%），差距约 **9 倍**。

5. **组件贡献与模型鲁棒性（RQ5）**：完整 ABEX 在全部 6 个消融对象上取得最高 QD-score，平均是 ExplorerOnly 的 **6.8 倍**；Ideator 的中间性能表明策略选择与细化都有独立贡献。开源模型（Gemma-4）在候选数量上甚至超过 GPT 配置，说明**框架有效性不依赖特定专有模型**，但平均候选质量 GPT 更高（平均 PD 2.80 vs 1.41 vs 1.22）。

## 8. 不足与局限

1. **应用范围有限**：所有 20 个 FUT 均为小型、无状态、无副作用、单函数、英文 docstring 的 Python 单元。未涉及有状态代码、多函数 API、大型真实项目、非英语规格或需要环境交互的系统。

2. **训练数据污染风险**：tritype、tcas、nextDate 等是长期存在的测试基准函数，可能出现在 LLM 训练数据中，边界知识可能来自记忆而非推理。论文承认这一威胁，但 ABEX 与单提示基线使用相同模型，记忆不能完全解释 2.8 倍的差距；仍需用专有/新编写函数进一步排除。

3. **成本与速度劣势**：LLM 调用使每次迭代成本远高于传统搜索，单次 500 迭代运行约 2.7M tokens。对简单数值函数，SETBVE 更快更便宜，ABEX 的性价比优势主要体现在非数值域或需要深入探索的质量场景。

4. **消融实验统计力度不足**：RQ5 消融和 LLM 比较每组仅运行一次（500 次迭代），无法评估随机方差，结果仅能作为指示性结论。

5. **行为描述子的领域盲区**：复用的四个描述子对数组等结构化输入可能无法捕捉语义上有意义的转换（如区分“元素变更”与“长度变更”），论文建议未来用 LLM 辅助生成更精细的描述子。

6. **VV 边界偏置**：当前默认提示配置偏向“有效-有效”边界，对 VE（有效-错误）和 EE（错误-错误）类型的探索不足，如 normalize 的空数组边界只有 4/10 次发现、binarySearch 的无序数组错误边界仅 5/10 次。

7. **协调器效率缺陷**：对于 circle 等简单函数，探索快速饱和后系统仍可能继续请求新策略，缺乏动态停止机制，造成资源浪费。

8. **解释性与复用价值未验证**：虽然策略以人类可读文本形式生成，但论文未实证评估测试人员对这些策略的可理解性，也未测量跨函数迁移策略的实际收益。

9. **基准选择的代表性限制**：20 个 FUT 虽覆盖不同输入类型，但以小型经典测试函数为主，缺乏对现代真实世界软件（如 Web 服务、解析器、编译器组件等）的评估。
